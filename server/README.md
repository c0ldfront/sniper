# Sniper 87 local server

An independent server that the original, unmodified Sniper 87 client can play
online against. It is a new implementation of the client's wire protocol, not
recovered historical server code. It binds to loopback only.

## Requirements

- Python 3, standard library only.
- The game files generated in the repository root:

  ```sh
  make assets SNIPER_ZIP=/path/to/sniper87.zip
  ```

  The server sends the game's `LOCAL.LVL` and `SNIPER.EXE` to clients that ask
  for map or update downloads. Both are read from `build/assets/files/`.

## Run

```sh
make serve              # port 38383, the game's LOCAL.LVL
make serve-open-arena   # an obstacle-free arena generated by the server
```

In the original client's Connection Information, enter `127.0.0.1` and
`38383`.

- **Accounts:** an unknown name gets the client's create-account prompt.
  Accounts and squads persist in `data/accounts.sqlite3`.
- **Scores:** kills, deaths and points reset on each login. Changing ships
  keeps the session score.
- **Stopping:** use Ctrl-C or SIGTERM.

Options (`python3 server.py -h`):

```sh
python3 server.py --port 38383 --data data
python3 server.py --map path/to/level.lvl      # or --map open-arena
python3 server.py --team-sharing               # team pickup sharing + ship reset on team change
python3 server.py --pickup-pool 1,2,3,8,9,10   # prize IDs ±1..21, or "none"
python3 server.py --push-asset news.txt --push-asset arena.lst
```

- **Maps:** restart the server to change the map. Clients download the new one
  on reconnect when its checksum differs.
- **Open arena:** a new level, a 768×768 ring of wall tiles with an empty
  interior, documented in `open-arena.json`.
- **Prizes:** the default periodic pool holds all 21 positive rewards. Prize 20
  is the v87 ghosting prize, not Continuum's AntiWarp.

## What it does

The original clients simulate weapons, collisions, damage, respawn and
ability effects themselves. The server:

- authenticates accounts; passwords are stored as salted scrypt hashes
- relays player state, chat, voice and attachments
- serves the map, news, arena list and update files
- keeps squads and scores
- distributes prizes

It sends the client its 72 offline configuration values, built from the table
in `../src/local_config.c`.

## Policy and limits

These behaviors are local policy, not known historical server behavior:

- prize distribution
- score awards from authenticated death reports
- duplicate-death suppression
- the player ID limit (127), queue and client limits, idle timeout
- optional team sharing

The historical server's anti-cheat, interest management, prize policy and
defaults are unknown. There is no internet deployment, no Wine-free client
runtime and no v40 compatibility.

## Layout and tests

```
server.py    arena, accounts, packet handling and CLI
protocol/    wire protocol: transport.py (reliable UDP), sniper_compression.py
             (the client's Huffman format), messages.py (application codec),
             socket_session.py (TCP bootstrap, UDP session, clock probes)
tests/       protocol, policy, live-socket and original-instruction tests
```

```sh
make test
```

The suite covers protocol vectors, transport loss, reordering and retry,
policy, and live server processes. The live tests cover restart persistence,
malformed peers and idle expiry.

Tests that compare against the original instructions (compression, sender
envelopes, settings) need `pefile` and `unicorn`, plus the generated
`SNIPER.EXE`. Without those modules, those tests are skipped.
